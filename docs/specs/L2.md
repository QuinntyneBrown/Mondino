# L2 - Detailed Requirements

Each requirement traces to one requirement in [L1.md](./L1.md). Acceptance criteria are written
Given / When / Then so each becomes a test. An acceptance test names the requirements it covers
in a header comment:

```typescript
// Acceptance Test
// Traces to: L2-001, L2-003
// Description: A person joins a team from its invite link with a postal code
```

Names, cities, postal codes and dates in the criteria are examples from the prototype's sample
team (Northwind) as the mocks show it at their "now", Monday 27 October 2025, 14:05 UTC; they are
the cast, not rules. "The viewer" is the teammate looking at the
screen.

## L2-001: Open an invite link
**Traces to:** L1-001

An invite link opens the Join screen for its team. The screen shows the team's name, how many
teammates are already on the globe, the initials of up to five of them, and the globe with their
pins, before the person has given anything.

**Acceptance Criteria:**
1. Given a valid invite link for the team Northwind with 11 teammates, when a person opens it, then the Join screen shows "Put yourself on the map.", "Joining Northwind · 11 already here" beside the initials of up to five of its teammates, and a globe with 11 pins.
2. Given a valid invite link, when the Join screen is shown before joining, then it shows of the teammates only a bare pin for each, with no name, city, local time or weather, and the initials and colour of up to five of them, the five who joined most recently; the initials are not tied to any pin, and the response carries no teammate's name, id or city.
3. Given an invite link that does not exist or has been withdrawn, when a person opens it, then the screen says the invite link cannot be used and shows no team name, no count and no pins.
4. Given a person who is already a teammate of the team on this device, when they open the team's invite link, then they are taken to the Globe screen and no second pin is made.
5. Given an invite link is being opened, when the answer has not arrived, then the Join screen shows "Put yourself on the map." with placeholders for the team and the form and a placeholder for the globe ("The globe is loading"), and announces "Opening your invite link…".
6. Given the backend does not answer, when a person opens an invite link, then the screen says "We couldn’t open this invite link" and that the link may be fine, offers "Try again", and shows no team name, no count and no pins; it does not say the invite link cannot be used.
7. Given one client has opened invite links too often and the open is refused with 429 (L2-045), when a person opens an invite link, then the screen shows the same state as when the backend does not answer: "We couldn’t open this invite link", with "Try again", and no team name, no count and no pins.

## L2-002: Give a name, a country and a postal code
**Traces to:** L1-001

The Join form has exactly three fields: the teammate's name, a country chosen from the supported
countries, and a postal code. It asks for no street address, e-mail address or phone number.

**Acceptance Criteria:**
1. Given the Join screen, when it is shown, then the form has the fields "Your name", "Country" and "Postal code" and no other field.
2. Given the Country field, when it is opened, then it lists the supported countries in alphabetical order; to begin with these are the thirteen: Australia, Brazil, Canada, Germany, Ghana, India, Ireland, Italy, Japan, Mexico, Sweden, United Arab Emirates and United States.
3. Given a name that is empty or only spaces, when the form is submitted, then the pin is not placed, the name field is marked invalid (`aria-invalid`) and a message says a name is needed.
4. Given a name longer than 60 characters, when the form is submitted, then the pin is not placed and a message gives the limit.
5. Given the Join screen with nothing typed, when it is shown, then the text "Only your city is shown. Your postal code stays private." is visible under the postal code field.
6. Given an empty postal code, when the form is submitted, then no lookup is made, the postal code field is marked invalid (`aria-invalid`) and a message says "Enter your postal code."
7. Given a form submitted with a name or a postal code missing, when the messages are shown, then a summary above the fields says what is missing ("Two things are missing"), links to each field, and takes focus.
8. Given the Join screen, when it is shown, then it names its sources: "Weather from Open-Meteo · Holidays from public calendars".

## L2-003: Look up the postal code
**Traces to:** L1-001

The postal code is looked up for the chosen country when the teammate leaves the field or
submits the form. While it is looked up the screen says so; when it is found the screen names
the city and the weather there, places the teammate's pin on the globe, and the button changes
from "Place my pin" to "Join" and the team's name.

**Acceptance Criteria:**
1. Given Italy and the postal code "20121", when the teammate leaves the postal code field, then the screen shows "Finding 20121…" and the button reads "Placing your pin…" and is disabled until the lookup answers.
2. Given the lookup finds Milan, when it answers, then the screen shows the city and region ("Milan, Lombardy"), that the pin is placed at city level, and the current temperature and weather there.
3. Given the lookup has found the city, when the screen updates, then the globe turns to that city, a new pin labelled "You" and the city appears there and pulses once (not under reduced motion), and the button reads "Join Northwind".
4. Given a found postal code, when the teammate changes the postal code or the country, then the found city and the new pin are removed and the button reads "Place my pin" again.
5. Given Canada and the postal code "L5B 3C1", when it is looked up, then the city found is Mississauga; and given "M5V 2T6", then the city found is Toronto.
6. Given a postal code typed with or without its usual space or hyphen and in upper or lower case ("l5b3c1", "L5B 3C1"), when it is looked up, then both find the same city.

## L2-004: A postal code that cannot be found
**Traces to:** L1-001

A postal code that does not match the country's format, or that the lookup does not know, is
refused with a message that names the postal code, the country and the form that country's
postal codes take. Nothing is placed.

**Acceptance Criteria:**
1. Given Italy and the postal code "2012", when it is looked up, then an alert says the postal code could not be found in Italy and that Italian postal codes have five digits, like 20121.
2. Given Canada and a postal code that does not fit the pattern letter-digit-letter digit-letter-digit, when it is looked up, then the alert says the postal code could not be found in Canada and gives the Canadian form ("Canadian postal codes look like A1A 1A1."), and no request is sent to the postal code source.
3. Given a postal code in the right form that the source does not know, when it is looked up, then the same alert is shown and no pin is placed.
4. Given an alert is shown, when the teammate edits the postal code, then the alert is removed.
5. Given the postal code source does not answer in time, when the lookup fails, then the message says the postal code could not be checked right now and offers to try again; it does not say the postal code is wrong.

## L2-005: Join the team
**Traces to:** L1-001

Once the city is found, joining adds the teammate to the team with a pin at that city, and takes
them to the Globe screen with their own pin selected.

**Acceptance Criteria:**
1. Given a name and a found postal code, when the teammate chooses "Join Northwind", then the team has one more teammate, and the Globe screen opens with the new teammate's pin on it.
2. Given a teammate who has just joined, when the Globe screen first shows their pin, then the pin pulses once to mark it as new (and does not pulse under reduced motion).
3. Given the join request fails, when the failure is reported, then the teammate stays on the Join screen with what they typed intact and a message offers to try again.
4. Given a teammate double-clicks "Join", when both requests arrive, then exactly one pin is made.
5. Given a team that has reached 500 teammates, when a person tries to join, then joining is refused with the code `team_full`, the screen says the team is full and that a team holds up to 500 teammates, and the "Join" button is disabled.
6. Given the teammate has chosen "Join Northwind", when the join request has not been answered, then the button reads "Joining Northwind…" and is disabled, and the name, country and postal code cannot be changed.

## L2-006: A pin is placed at the city
**Traces to:** L1-002

A postal code is resolved to its city: the municipality it lies in, the level at which
Mississauga and Toronto are different places. The pin takes the city's own position, never the
position of the postal code.

**Acceptance Criteria:**
1. Given two teammates in Toronto with different postal codes, when their pins are read from the backend, then both carry the same position, the position of Toronto.
2. Given a teammate in Mississauga and one in Toronto, when the globe is shown, then their pins are at different positions and each is labelled with its own city.
3. Given any teammate, when their pin's position is compared with the position of their postal code, then the pin's position is the city's and does not change when the postal code changes within the same city.
4. Given a postal code in a rural area that belongs to no city, when it is looked up, then the pin is placed at the nearest named locality the source gives, and that locality's name is shown as the city.

## L2-007: A postal code is never shown to another teammate
**Traces to:** L1-002

A postal code is returned only to the teammate it belongs to, on their own Join and Profile &
Settings screens. Everything another teammate receives carries the city and country only.

**Acceptance Criteria:**
1. Given a teammate reads their team, when the response is inspected, then no other teammate's postal code, nor any part or hash of it, is present in it.
2. Given a teammate's panel on the Globe screen, a row on the Team screen or a moment on the Moments screen, when another teammate looks at it, then it shows the city and country and no postal code.
3. Given a teammate reads their own profile, when the response is inspected, then it carries their own postal code and no one else's.
4. Given any screen, when the browser's storage (local, session, IndexedDB, cookies) and the address bar are inspected, then no postal code is present in them.
5. Given a request for another teammate's profile, when it is made, then it is refused with 403 or 404 and returns no postal code.

## L2-008: The globe is three-dimensional and drawn from Blender-built assets
**Traces to:** L1-003

The globe is a lit, shaded 3D model: land raised from the sea, soft shadows, rounded forms and
saturated colour, in the look of a modern animated film. It has colours of its own, as the mocks
draw it: a bright blue ocean with a deeper rim, green land with sand and forest, white ice and
cloud, a dusk-shaded night side and an ink outline. The brand's pin and sun mark the people and
moments on it. Its model and textures are made in Blender, exported to a web format and
bundled with the app.

**Acceptance Criteria:**
1. Given the Globe screen on a device with WebGL, when the globe is drawn, then it is rendered in 3D with perspective and lighting, and continents are recognisable.
2. Given the globe's assets, when the app is built, then they are served from the app's own origin, and the browser makes no request to any other origin to draw the globe.
3. Given a device without WebGL, or where the globe's assets fail to load, when the Globe screen opens, then a still picture of the globe is shown in its place, without pins, with a notice that says so and links to the Team screen, and every teammate is still reachable through the panel and the Team screen.
4. Given a low-power device (see L2-046), when the globe is drawn, then it uses a lower level of detail and keeps its look: lighting, colour and pins are unchanged.
5. Given a first-time visitor, when the Globe screen opens, then a placeholder in the globe's place is shown until the 3D globe is ready, and the layout does not shift when it appears.

## L2-009: The globe turns, spins and holds
**Traces to:** L1-003

Left alone, the globe turns slowly on its own. It is dragged to spin, by pointer or touch, and
turned with the arrow keys. When a pin is selected the globe turns to bring it to the front and
holds there.

**Acceptance Criteria:**
1. Given the Globe screen with no pin selected and no interaction, when 5 seconds pass, then the globe has turned eastward on its own.
2. Given the globe, when the teammate drags across it by mouse or by touch, then the globe spins with the drag and stops turning on its own until 5 seconds after the drag ends.
3. Given a pin is selected, when the selection is made, then the globe turns so the pin faces the viewer within 1 second and stays there until the selection is cleared.
4. Given the globe has keyboard focus, when an arrow key is pressed, then the globe turns in that direction by a fixed step.
5. Given reduced motion is requested, when the Globe screen is shown, then the globe does not turn on its own, and turning to a selected pin happens without animation.
6. Given the browser tab is hidden, when it stays hidden, then the globe neither turns nor draws, and it resumes when the tab is shown again.
7. Given a vertical drag that begins on the globe on a phone, when the globe cannot turn further in that direction, then the page scrolls, so the globe never traps the page.
8. Given a globe that is not interactive (the Join screen's globe, and the small globe on Profile & Settings), when it is shown, then it does not turn on its own and cannot be dragged or turned by keys; it turns only to the pin it is given.

## L2-010: The night side is shaded
**Traces to:** L1-003

The half of the globe where it is night right now is shaded, from the sun's real position at the
current time, and the shading moves as time passes.

**Acceptance Criteria:**
1. Given the clock says 12:00 UTC on 21 March, when the globe is drawn, then a point at longitude 0° on the equator is lit and a point at longitude 180° is shaded.
2. Given a teammate whose local time is 02:00, when the globe is turned to their pin, then their pin sits in the shaded half.
3. Given the Globe screen stays open for an hour, when the hour has passed, then the edge of the shading has moved westward by about 15° of longitude.
4. Given a pin on the night side, when it is shown, then the pin and its label remain as readable as on the day side (contrast per L2-041).
5. Given a width of 576 px or more, when the Globe screen is shown, then a legend names "Night side", "Moment this week" and "Drag to spin".

## L2-011: A pin shows a teammate
**Traces to:** L1-004

A pin shows the teammate's initials in the teammate's own colour, and a label beside it with
their local time, the weather and the temperature. The viewer's own pin is marked as theirs.

**Acceptance Criteria:**
1. Given the teammate Tomás Herrera in Mexico City, when his pin is shown with its label, then it carries the initials "TH", his local time, a weather icon and the temperature.
2. Given a team, when each teammate joins, then they are given a colour from the pin palette that differs from the teammates nearest to them on the globe where the palette allows.
3. Given the viewer's own pin, when it is shown, then it is marked "(you)" wherever a name appears and is distinguishable from other pins by more than colour.
4. Given a teammate who has turned off "Share my local weather", when their pin is shown, then it carries their local time and no weather or temperature.
5. Given a pin on the far side of the globe, when the globe is drawn, then that pin and its label are hidden, and they appear as the globe turns them into view; a pin near the globe's edge is drawn fainter and without its label until it is lifted.
6. Given a name whose first characters are not letters or which is one word, when the pin is shown, then the initials are the first character of up to the first two words, and the pin is never blank.

## L2-012: A pin lifts out when pointed at, focused or selected
**Traces to:** L1-004

On a small globe pins are small. A pin that the pointer is over, that has keyboard focus, or
that is selected rises from the globe's surface, grows, comes in front of its neighbours and
shows its label, so the teammate can be read clearly. When the pointer leaves it settles back.

**Acceptance Criteria:**
1. Given a pin at rest, when the pointer moves over it, then within 200 ms the pin is drawn larger and raised above the surface, in front of every neighbouring pin, with its label showing the teammate's name, city, local time and weather.
2. Given a lifted pin, when the pointer leaves it and it is not selected, then it settles back to its resting size and place.
3. Given the globe has keyboard focus, when Tab moves to a pin, then that pin lifts exactly as under the pointer, and Enter or Space selects it.
4. Given a touch device, where there is no hover, when a pin is tapped, then it is selected and lifts, and a second tap elsewhere on the globe clears the selection.
5. Given a selected pin, when it stays selected, then it stays lifted and its teammate's details are shown in the panel (L2-023).
6. Given reduced motion is requested, when a pin is pointed at, then it changes to its lifted size and shows its label without the rising animation.
7. Given a pin at rest at any globe size, when its hit area is measured, then it is at least 44 × 44 CSS px.

## L2-013: Pins that are close together stay distinguishable
**Traces to:** L1-004

Teammates in the same city, or in cities close together at the current size of the globe, are
never drawn on top of one another so that one is hidden.

**Acceptance Criteria:**
1. Given three teammates in Toronto, when the globe shows Toronto, then three pins are visible, fanned around the city's position, and each can be pointed at and selected on its own.
2. Given teammates in Milan, Berlin, Stockholm and Dublin on a globe 320 px wide, when the globe shows Europe, then each teammate can be selected on their own, from their own pin or through a group pin (criterion 3), and no label overlaps another pin.
3. Given more pins in one place than can be fanned at the current size, when the globe shows them, then they are drawn as one group pin with a count, and selecting it lists its teammates in the panel to choose from.
4. Given a globe less than 400 px wide, when it is shown, then pins are drawn smaller and a label is shown only for the pin that is lifted or selected.
5. Given a label, when it is placed, then it sits beside its pin, inside the globe's area and clear of other pins.

## L2-014: Local time
**Traces to:** L1-005

A teammate's local time is worked out in the browser from the time zone of their pin and one
shared clock. It is shown as a 24-hour or 12-hour time as the viewer has chosen, with the day of
the week and the date where a panel shows it ("Monday 27 Oct").

**Acceptance Criteria:**
1. Given the clock says 14:05 UTC on 27 October 2025 and a teammate in Mexico City, when their local time is shown on a 24-hour clock, then it reads "08:05"; on a 12-hour clock, "8:05 am".
2. Given a teammate in Bengaluru (UTC+5:30), when the clock says 14:05 UTC, then their local time reads "19:35".
3. Given a screen showing local times, when the minute changes, then every local time on the screen changes together, from one clock, within one second of the minute.
4. Given a daylight-saving change in a teammate's time zone, when the clock passes it, then their local time and offset follow the zone's rule with no reload.
5. Given a teammate in Melbourne when the viewer in Milan is on Monday evening, when the panel is shown, then it shows Melbourne's own day, "Tuesday 28 Oct".
6. Given the backend's response for a pin, when it is inspected, then it carries the pin's time zone as an IANA name and no local time.

## L2-015: Status follows the local hour
**Traces to:** L1-005

A teammate's status is decided only by their local hour. It is never taken from activity,
presence or anything the teammate does.

| Local time | Status |
|---|---|
| 07:00 to 08:59 | Early morning |
| 09:00 to 17:59 | Working hours |
| 18:00 to 22:59 | Evening |
| 23:00 to 06:59 | Probably asleep |

**Acceptance Criteria:**
1. Given a local time of 06:59, 07:00, 08:59, 09:00, 17:59, 18:00, 22:59 and 23:00, when the status is worked out, then it is respectively Probably asleep, Early morning, Early morning, Working hours, Working hours, Evening, Evening and Probably asleep.
2. Given a teammate at 08:59 local time shown as "Early morning", when the clock reaches 09:00, then their status changes to "Working hours" with no reload.
3. Given any status, when it is shown, then it is given as its words, never by colour alone.
4. Given a teammate who has turned off "Show when I’m outside working hours", when another teammate sees them outside 09:00 to 18:00, then no status is shown for them, they are not counted as asleep on the Globe screen, and on the Team screen they are listed under All only, not under Asleep nor in its count (L2-028).
5. Given Saturday or Sunday, when the status is worked out, then the same table applies; Mondino keeps no calendar of working days.

## L2-016: Offset from the viewer
**Traces to:** L1-005

A teammate's offset is the difference between their local time and the viewer's, in hours and,
where the zones differ by part of an hour, minutes.

**Acceptance Criteria:**
1. Given a viewer in Milan (UTC+1) and a teammate in Mexico City (UTC−6), when the offset is shown, then it reads "7 h behind" on their Team row and "7 h behind you" on their panel.
2. Given a viewer in Milan (UTC+1) and a teammate in Bengaluru (UTC+5:30), when the offset is shown, then it reads "4 h 30 min ahead" on their Team row and "4 h 30 min ahead of you" on their panel.
3. Given a viewer and a teammate whose clocks read the same, when the offset is shown, then it reads "Same time" on their Team row and "Same time as you" on their panel, never "0 h".
4. Given the viewer's own pin or row, when it is shown, then no offset is given.
5. Given a daylight-saving change on one side only, when it has passed, then the offset shown has changed by one hour.

## L2-017: Overlap of working hours
**Traces to:** L1-005

The overlap between the viewer and a teammate is the part of both their working days (09:00 to
18:00 local) that coincides, given on the viewer's own clock, with a bar that draws both working
days, the part they share and the time now across the viewer's day.

**Acceptance Criteria:**
1. Given a viewer in Milan (UTC+1) and a teammate in Mexico City (UTC−6), when the overlap is shown, then it is 16:00 to 18:00 on the viewer's clock, two hours.
2. Given a viewer in Milan and a teammate in Melbourne (UTC+11), when the overlap is shown, then it reads "None today", says the two share no working hours and gives the teammate's working day on the viewer's clock, 23:00 to 08:00, and the bar shows no shared part.
3. Given a viewer and a teammate in the same time zone, when the overlap is shown, then it is 09:00 to 18:00.
4. Given the viewer has chosen the 12-hour clock, when the overlap is shown, then its times are 12-hour times, a time on the hour without its minutes ("4 pm to 6 pm").
5. Given the overlap bar, when it is read by a screen reader, then the overlap is given as text with its start, end and length.
6. Given the viewer's own pin is selected, when the panel is shown, then no overlap is shown.

## L2-018: Current weather at a teammate's city
**Traces to:** L1-006

Each pin carries the current temperature and one of a fixed set of conditions (clear, partly
cloudy, cloudy, rain, showers, storm, fog, wind) for its city, from Open-Meteo by way of the
backend. Conditions are shown as an icon with its word ("Clear", "Partly cloudy", "Cloudy",
"Rainy", "Showers", "Stormy", "Foggy", "Windy"); at night a clear or partly cloudy sky uses its
night icon.

**Acceptance Criteria:**
1. Given the weather source reports 13 °C and fog for Milan, when a teammate in Milan is opened, then the panel shows "13°C" and "Foggy in Milan" with the fog icon.
2. Given a teammate whose local time is in "Probably asleep" hours with clear weather, when their weather is shown, then the night form of the icon is used.
3. Given a condition from the source that is not one of the eight, when it is mapped, then it is shown as the nearest of the eight, and never as an empty or broken icon.
4. Given weather was fetched for a city less than 15 minutes ago, when another teammate in the same city is read, then the source is not called again.
5. Given a weather icon, when it is read by a screen reader, then the condition is announced as its word.

## L2-019: Temperature in °C or °F
**Traces to:** L1-006

Temperatures are shown in the unit the viewer has chosen, as whole degrees with tabular
figures: with the unit on a panel ("13°C") and as degrees alone on a pin and a Team row ("13°").
A new teammate's unit starts from their country: °F for the United States, °C elsewhere.

**Acceptance Criteria:**
1. Given a temperature of 13 °C and the viewer's unit °F, when it is shown, then it reads "55°F" on a panel and "55°" on a pin and a Team row.
2. Given a temperature of −0.4 °C, when it is shown in °C, then it reads "0°C", never "−0°C".
3. Given the viewer changes the unit in Profile & Settings and saves, when any screen is shown afterwards, then every temperature on it uses the new unit.
4. Given a teammate who joins from the United States, when they first see a temperature, then it is in °F; from Canada or Italy, in °C.

## L2-020: The four kinds of moment
**Traces to:** L1-007

A moment is something happening where a teammate lives. It has a kind, a title, a date local to
that place and one line of detail. There are exactly four kinds: a holiday, Formula 1, a local
event and sport. A moment belongs to a teammate when it happens where they live:

| Kind | Belongs to a teammate when |
|---|---|
| Holiday | It is a public holiday in the teammate's country, or in their region where the holiday is regional |
| Formula 1 | A race weekend is held in the teammate's country, or it is a dated happening in that race's own calendar, such as its tickets going on sale |
| Local event | The event is held within 100 km of the teammate's city |
| Sport | A home fixture or major sporting day is held within 100 km of the teammate's city |

**Acceptance Criteria:**
1. Given a teammate in Dublin and the October Bank Holiday on 27 October, when their moments are read, then they include a holiday moment titled "October Bank Holiday" dated 27 October.
2. Given a teammate in Milan and a teammate in Austin, when the Italian Grand Prix weekend is in the calendar, then it is a Formula 1 moment for the teammate in Milan and not for the teammate in Austin.
3. Given a teammate in Mississauga and a teammate in Toronto, when the Toronto Raptors have a home game, then it is a sport moment for both, and not for a teammate in Ottawa.
4. Given a regional holiday that applies to Lombardy only, when moments are read, then it belongs to a teammate in Milan and not to a teammate in Rome.
5. Given two teammates in the same city with the same moment, when moments are listed, then the moment appears once for each teammate it belongs to, each naming its teammate.
6. Given a moment's date, when it is compared with "today", then "today" is the date in the moment's own place, so a moment dated 4 November in Melbourne is "today" while it is 4 November in Melbourne.
7. Given a moment from an outside source, when its title and detail are shown, then they are rendered as text and limited to 80 and 160 characters, cut with an ellipsis.
8. Given a teammate in Milan and a teammate in Austin, when the Italian Grand Prix's calendar has its tickets going on sale on 12 November, then "Monza tickets on sale", dated 12 November, is a Formula 1 moment for the teammate in Milan and not for the teammate in Austin.

## L2-021: A moment marker on the pin
**Traces to:** L1-007

A pin whose teammate has a moment today or in the next 7 days carries a moment marker beside
it, in the sun colour, showing an emblem for the moment so it can be told at a glance: a race
car for Formula 1, a team's emblem for a sport fixture, and so on. An emblem that belongs to
someone else (a team's or a series' own logo) is used only where Mondino holds the right to use
it; otherwise the marker shows Mondino's own icon for the kind and the title names the team or
race.

**Acceptance Criteria:**
1. Given a teammate in Dublin with a holiday today, when the globe shows their pin, then a moment marker with the holiday icon sits beside the pin.
2. Given a teammate whose nearest moment is 8 days away, when the globe shows their pin, then the pin carries no moment marker.
3. Given a teammate with a Formula 1 moment and a holiday in the next 7 days, when their pin is shown, then the marker shows the nearer of the two, and a count shows that there are two.
4. Given a moment whose subject has an emblem Mondino has the right to use, when its marker is shown, then it shows that emblem; and given one it does not, then it shows the icon of the moment's kind.
5. Given a pin with a moment marker, when the pin is pointed at, focused or selected and lifts, then its label shows the moment's title and when it happens ("Today", "Tomorrow", "In 3 days") as text, and the pin's accessible name gives both; the marker is not a control of its own.
6. Given a moment today, when its marker is shown, then it is visibly stronger than a marker for a moment later in the week, by size or a ring, not by colour alone.
7. Given a globe less than 400 px wide, when moment markers are shown, then each is still at least 16 px across and does not cover its pin's initials.

## L2-022: Only the kinds the viewer chose are shown on the globe
**Traces to:** L1-007

The viewer chooses which kinds of moment mark pins on the globe. All four kinds are on to begin
with. The choice changes what the viewer sees and nothing for anyone else.

**Acceptance Criteria:**
1. Given a new teammate, when they first open the Globe screen, then moments of all four kinds mark pins.
2. Given the viewer has turned off "Formula 1 race weekends", when the globe shows a teammate whose only moment this week is a race, then that pin carries no moment marker, and the race is absent from "This week around the world".
3. Given the viewer has turned off a kind, when they open the Moments screen, then moments of that kind are still listed there and can be filtered.
4. Given the viewer has turned off every kind, when the globe is shown, then no pin carries a moment marker and "This week around the world" says "Nothing to show: every kind of moment is turned off for your globe." with "Choose what shows", which leads to Profile & Settings.
5. Given one teammate turns a kind off, when another teammate looks at the globe, then their view is unchanged.

**Acceptance Criteria:**
1. Given one client makes more than 10 postal code lookups in a minute, when the next arrives, then it is refused with 429 and a `Retry-After` header, and the outside source is not called.
2. Given one client opens more than 30 invite links in a minute, when the next arrives, then it is refused with 429, so invite links cannot be guessed at speed.
3. Given one client makes more than 5 join requests in a minute, when the next arrives, then it is refused with 429.
4. Given a postal code lookup, when it is made, then it needs a valid invite link's token, so the lookup cannot be used by someone with no invite link.
5. Given a postal code lookup or a join request refused with 429, when it is shown on the Join screen, then the message says "That was a lot of tries in a short time. Wait a moment, then try again.", and what they typed is kept. A refused open of an invite link has nothing typed to keep and shows the state of L2-001.
6. Given every other endpoint except the health endpoints (L2-051), when it is called without a teammate session, then it is refused; no endpoint is open by omission.

## L2-046: Fast to load and smooth to turn
**Traces to:** L1-015

Mondino opens quickly on a phone and the globe turns smoothly on an ordinary laptop. The
reference devices are a mid-range phone on a 4G connection (throttled 1.6 Mbps, 150 ms) and a
laptop with integrated graphics.

**Acceptance Criteria:**
1. Given the reference phone and a first visit, when the Globe screen is opened, then the largest contentful paint is within 2.5 seconds and the layout shift score is under 0.1.
2. Given the reference phone, when the Globe screen is opened, then the 3D globe is drawn and can be spun within 5 seconds, and the heading, counts and panel are usable before it.
3. Given the reference laptop and a team of 100, when the globe is dragged, then it draws at 50 frames a second or more; and on the reference phone, 30 or more.
4. Given any interaction (selecting a pin, changing a filter, typing in a field), when it is made, then the screen responds within 200 ms (INP).
5. Given the built app, when its bundles are measured, then the initial bundle is at most 150 kB compressed and holds neither the globe's renderer nor its assets, which are loaded only when a globe is first drawn.
6. Given a low-power device, detected from a sustained frame rate under 30, when the globe is running, then it steps down its level of detail and resolution until the frame rate recovers.
7. Given a repeat visit, when the app is opened, then the globe's assets are served from the browser's cache with a long-lived, content-hashed address.
8. Given a team of 500, when the team is read from the backend, then the 95th-percentile response time is under 300 ms and the response is compressed.

## L2-047: Steady memory for a whole day
**Traces to:** L1-015

Mondino is left open all day. It uses no more memory at the end than at the start, and every
screen gives its memory back when the teammate leaves it.

**Acceptance Criteria:**
1. Given the Globe screen left open for 8 simulated hours with the clock ticking, when the heap is measured after garbage collection at the start and the end, then it has grown by no more than 5%.
2. Given the teammate enters and leaves the Globe screen 20 times, when the heap is measured after garbage collection, then it is within 5% of its size after the first visit, and no WebGL context, animation loop, timer or listener from an earlier visit remains.
3. Given any screen with local times, when its timers are counted, then one shared clock drives every local time, however many pins there are.
4. Given the tab is hidden for an hour, when it is shown again, then local times, statuses and the night side are correct at once, and no work was done drawing the globe while hidden.
5. Given a team of 500, when the Team and Moments screens are scrolled from top to bottom, then the number of rows in the page stays under a fixed limit.
6. Given a teammate leaves a screen while a request is pending, when they leave, then the request is cancelled.

## L2-048: Fresh without reloading
**Traces to:** L1-015

A screen left open stays true: weather, moments and the team itself are refreshed quietly.

**Acceptance Criteria:**
1. Given the Globe screen left open and visible, when 15 minutes pass, then the team's pins and weather are read again and the screen updates without losing the selection or the globe's position.
2. Given a new teammate joined while the screen was open, when the next refresh arrives, then their pin appears and pulses once, and the counts update.
3. Given the tab was hidden for more than 15 minutes, when it is shown again, then a refresh is made at once.
4. Given the tab is hidden, when it stays hidden, then no refresh is made.
5. Given the date changes in a teammate's city, when the clock passes their midnight, then their moments move between Today, This week and Later with no reload.
6. Given a refresh fails, when a screen is open, then it keeps what it shows, a banner says "Couldn’t refresh just now." with the time its weather and moments are from and offers "Try now", and the banner goes, with no message, as soon as a refresh succeeds (see L2-049).

## L2-049: A pin still shows its local time when a source fails
**Traces to:** L1-016

The postal code lookup, the weather and the calendars are called only by the backend, each with
a timeout, and their answers are cached. When one fails, everything that does not depend on it
is still shown.

**Acceptance Criteria:**
1. Given the weather source is failing, when a teammate reads their team, then the response succeeds, every pin has its city, position and time zone, and weather is marked as unavailable rather than given as zero.
2. Given weather is unavailable for a pin, when the pin, panel and Team row are shown, then they show the local time and status; the pin's label leaves the weather out, and the weather's place in the panel and the Team row says it is unavailable; nothing is broken or blank.
3. Given the weather source is failing but a cached answer less than 3 hours old exists, when the team is read, then the cached weather is given.
4. Given a calendar source is failing, when moments are read, then moments of the other kinds are still given, with the last cached moments of the failing kind.
5. Given any outside source takes longer than 5 seconds, when the call times out, then the request that needed it completes with what the backend has; no response to a browser waits longer than 6 seconds on an outside source.
6. Given an outside source keeps failing, when calls continue, then the backend stops calling it for a short interval before trying again, and does not queue calls without limit.
7. Given the backend itself cannot be reached, when a screen is open, then it keeps its last data, the clocks keep ticking, and a message says it could not be refreshed and will try again.
8. Given a screen's first read has not answered yet, when the screen is shown, then it shows its loading state: a placeholder in the shape of the content, announced politely with the mock's words (such as "Loading your team…").
9. Given a screen's first read fails, when the screen is shown, then it shows its error state with the mock's words (such as "We couldn’t load your team") and "Try again", and no stale or partial team data.

## L2-050: An outside source learns a place and nothing else
**Traces to:** L1-016

A call to an outside source carries a place (a country and postal code, or a position, or a
country and year) and never a teammate's name, their team or anything that identifies them.

**Acceptance Criteria:**
1. Given a postal code lookup, when the request to the outside source is inspected, then it carries the country and postal code and no name, team, teammate id, session or client address.
2. Given a weather request, when it is inspected, then it carries the city's position, rounded to two decimal places, and nothing else about the teammate.
3. Given two teammates in the same city, when their weather is needed, then one call is made for the city.
4. Given any screen, when the browser's requests are recorded, then the browser itself calls no outside source (see L2-044).

## L2-051: Telemetry that carries no teammate
**Traces to:** L1-017

The backend emits OpenTelemetry traces, metrics and logs, enough to see its health and the
health of each outside source. None of it carries a name, a postal code, a position, a city, a
token, a query string or a body, and a route is recorded as its template.

**Acceptance Criteria:**
1. Given a join with the name "Sofia Bianchi" and postal code "20121", when every log, span and metric it produced is searched, then neither value, nor Milan, nor its coordinates, nor the invite link's token appears.
2. Given a request to a team's endpoint, when its span is inspected, then the route is recorded as its template (`/api/teams/{teamId}/pins`), with no id, query string or body.
3. Given calls to the postal code, weather and calendar sources, when metrics are read, then each source has a count of calls, failures and time-outs and a latency histogram, labelled by source and outcome only.
4. Given the backend, when its health endpoints are called, then liveness and readiness are reported without exposing configuration, versions of dependencies or teammate data.
5. Given an unhandled error, when it is logged, then the log carries the error's type and a correlation id that also appears in the ProblemDetails returned, and no request data.
6. Given the frontend, when it is used, then it sends no analytics or telemetry to a third party.
