Theming

Light and dark from one set of roles. A theme changes what a role points at, never a component.

Status: stableSince v1.0
  • Overview
  • Token tiers
  • How a theme applies
  • Usage
  • tokens.json
  • Tokens

Overview

Light is the default and is what the Magic Patterns prototype draws. Dark is this system’s own: night becomes the canvas and paper becomes the ink; pin, sun and leaf keep their hue; the globe keeps its colours. The system follows the device’s preference unless a page forces a theme.

Token tiers

TierPrefixExampleWho reads it
Primitive--palette-*, --font-*--palette-ink: #17223aSemantic tokens only
Semantic--color-*, --text-*, --space-*, --radius-*, --shadow-*, --duration-*, --z-*, --layout-*--color-accent: var(--palette-ink)Components and pages. A theme overrides this tier.
Component--btn-*, --field-*, --pin-*, --dialog-*, --toast-*--btn-primary-bg: var(--color-accent)One component, in components.css

How a theme applies

:root, [data-theme="light"] { … }            /* light: the default */
[data-theme="dark"] { … }                     /* dark, when a page or a part of it asks */
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) { … }       /* dark, when the device prefers it */
}

Each theme sets color-scheme so the browser’s own controls and scrollbars follow. prefers-contrast: more strengthens hairlines and muted text; forced colours hand the focus ring and edges to the system.

Usage

  • To change the brand’s colours, change primitives. To change what “accent” means, change the semantic token. To change how one component looks, change its component token.
  • A new theme is one more [data-theme="name"] block that overrides semantic tokens, with its pairs passing the contrast check.
  • Keep the two dark blocks identical: the attribute one and the media-query one.
  • Never write a colour, a size or a time in a component or a page.

tokens.json

tokens/tokens.json is the same tokens in the W3C Design Tokens format, generated from tokens.css: nested by name, aliases kept as references, dark values under $extensions. Generate constants for another platform from it; never edit it by hand.
