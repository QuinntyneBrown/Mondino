Foundation

Accessibility

Mondino meets WCAG 2.2 AA by construction. Every component page says how; this page is the whole commitment.

Status: stableSince v1.0
  • Overview
  • Perceivable
  • Operable
  • Understandable
  • Robust
  • Testing
  • Interaction tokens

Overview

Everyone on the team can see where a teammate is and what it is like there: by keyboard, by touch, with a screen reader, with enlarged text, with reduced motion, in light or dark. Nothing on the globe is available only as a picture.

Perceivable

  • Text holds 4.5:1 against every surface it sits on, large text and the edge of a control 3:1, in both themes. The pairs are checked by a script.
  • Colour is never the only carrier: a status has its words, a chosen option a tick or a fill and an attribute, an invalid field an icon and a message, today’s moment marker a ring and a larger size.
  • A pin and its label stay readable on the night side of the globe as on the day side.
  • Every icon that carries meaning has a text equivalent. The weather is always a word as well.
  • Times and temperatures use tabular figures, so they do not shift as they change.
  • At 200% text size every screen keeps its content and controls with no sideways scroll at 1280 px.

Operable

  • Every control is reached by Tab in the order the screen reads, and operated by the keyboard alone.
  • “Skip to content” is the first focusable element on every screen.
  • One focus ring everywhere: 2 px, 2 px off the edge, at least 3:1.
  • Every touch target is at least 44 × 44 px.
  • The globe turns with the arrow keys; each pin is a button; Enter or Space selects it; Escape clears.
  • A dialog keeps focus inside it, closes on Escape, and returns focus to what opened it.
  • Nothing needs two fingers or a drawn path. Nothing times out.

Understandable

  • The page’s language is set, and each screen has one <h1> and headings in order.
  • Every field has a visible label. An error says what to fix, sits under its field, and is tied to it.
  • A form submitted with errors gets a summary at the top that takes focus and links to each field.
  • Nothing typed is lost when something fails.
  • The same thing is named the same way on every screen: teammate, pin, moment, postal code, local time.

Robust

  • Native elements first: a button is a <button>, a link an <a>, a table a <table>.
  • A state assistive technology must know is an attribute and is styled through it: aria-current, aria-pressed, aria-selected, aria-checked, aria-invalid, aria-busy, disabled.
  • The globe is one labelled group holding a list of pins; the 3D canvas is hidden from the accessibility tree.
  • A change of panel is announced once, politely. A lookup’s result is announced; its error is an alert. The clocks ticking each minute are not announced.
  • Reduced motion is honoured through the duration tokens and by the globe.

Testing

  1. Run the contrast check: check_contrast.py docs/design-system/tokens/tokens.css.
  2. Run an automated scan (axe, WCAG 2.2 AA rules) on every screen in every state. It reports nothing.
  3. Tab through each screen: order, visible focus, no trap outside a dialog.
  4. Read the Globe with a screen reader: the globe is one group, each pin is named in full, selecting a pin is announced once.
  5. Set text to 200%, turn on reduced motion, switch to dark, and look again.

The accessibility sweep is written and kept current, and is run when a person asks.
