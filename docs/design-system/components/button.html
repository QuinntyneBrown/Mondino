Button

A button does something: places a pin, joins a team, saves a change, tries again.

WCAG 2.2 AAStatus: stableSince v1.0

Overview

Use a button for an action on the current screen. Each screen has one primary button at most: “Place my pin”, “Join Northwind”, “Email me a sign-in link”, “Create team”, “Save changes”, “Try again”. Everything else is a secondary button, a link-style button or an icon button.

To go somewhere, use a link. To choose between views or filters, use a segmented control or a chip.

Anatomy

Its parts, in reading order:

  1. Leading icon (optional)16 px, takes the label’s colour
  2. LabelA verb phrase in sentence case
  3. ContainerA pill, 44 px tall, 16 px padding

Variants

Primary is ink and carries the one thing the screen is for. Secondary is an outline. Danger is for leaving the team. Link-style is for a quiet action in running layout: “Leave Northwind”, “Reset link”. Icon-only closes a panel or a dialog, dismisses a toast, and is “Invite teammate” in the header under 768 px. On-inverse sits on the save bar.

Sizes

Medium is the default. Large is the one submit button of a form. Small sits inside a bar, a card or an alert; its touch target is still 44 px on a phone because its container pads it.

Responsive behaviour

A form’s submit button is a block at every width. In a dialog under 576 px the buttons stack, confirm above cancel, each the full width of the sheet; from 576 px they sit in a row at the right. “Invite teammate” in the header is an icon alone, 44 × 44 px, under 768 px and shows its words from 768 px; its accessible name is the same at every width. “Look up” beside the postal code on Profile & Settings drops under the fields under 576 px.

Theming

It reads semantic tokens only, so light and dark both come from tokens.css. To re-theme it, override the tokens listed under Tokens at :root or in a [data-theme] block; never write a colour in the component.

Accessibility

Role and pattern

A native <button>. A button that only looks like a link is still a button. An icon-only button has an aria-label that names what it acts on (“Close Tomás Herrera”, “Invite teammate”). A button that opens a dialog says so with aria-haspopup="dialog".

Keyboard

KeyAction
Enter / SpaceActivates the button
TabMoves to the next control

Focus

A 2 px ring in --color-focus-ring, 2 px off the edge. A busy button keeps focus and ignores further presses.

Labelling

The label is the accessible name. While busy the button carries aria-busy="true" and its label says what is happening (“Sending link…”, “Creating your team…”, “Leaving…”). A button that has done its work may say so in place: “Copy link” reads “Copied”.

Contrast

Primary label --color-fg-on-accent on --color-accent
Danger label --color-fg-on-danger on --color-danger-solid
Secondary edge --color-border-strong on --color-bg-canvas

Motion

Colour and size changes take --duration-fast. Reduced motion sets every duration token to nothing, so the change is instant with no extra rule.

Touch

The target is at least 44 × 44 px (--target-comfortable).

Content

Start with a verb and name the thing: “Place my pin”, “Join Northwind”, “Save changes”, “Copy link”, “Look up”, “Email me a sign-in link”. Never “OK”, “Submit” or “Yes”. A busy label is the same verb in progress, ending with an ellipsis. After a failure the button says what it will do again: “Try again”, “Try joining again”.
