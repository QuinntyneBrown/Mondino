Lookup message

The line under the postal code that says what Mondino did with it: kept it private, is finding it, found the city, or could not.

WCAG 2.2 AAStatus: stableSince v1.0

Overview

It sits in one place under the country and postal code and changes with the lookup. Before anything is typed it carries the privacy promise. It is the only place a found city and its weather are named before the teammate joins or saves. On Join and Create Team the lookup starts when the teammate leaves the postal code; on Profile & Settings it starts from “Look up”, and the message says the pin moves only on saving.

Anatomy

Its parts, in reading order:

  1. IconLock, spinner, pin or alert: one per state
  2. City and regionBold, in the default colour
  3. What it means“pinned at city level”, then the weather

Sizes

It has one size.

States

Its four variants are its states; each is shown under Variants.

Responsive behaviour

It wraps to as many lines as it needs and keeps 44 px of height when it is one line, so the button under it does not jump as the message changes.

Theming

It reads semantic tokens only, so light and dark both come from tokens.css. To re-theme it, override the tokens listed under Tokens at :root or in a [data-theme] block; never write a colour in the component.

Accessibility

Role and pattern

It lives in an aria-live="polite" region, so finding and found are announced. Not found is role="alert".

Keyboard

It is not focusable and takes no keys; it is read in place by a screen reader.

Focus

Focus stays in the postal code field while the message changes.

Labelling

The postal code input points at it with aria-describedby.

Contrast

Private and finding --color-fg-muted on --color-bg-canvas
Found --color-fg-default on --color-bg-canvas
Not found --color-danger-fg on --color-bg-canvas

Motion

The spinner turns while finding. Under reduced motion it stands still and the words carry the state.

Touch

It is not a control.

Content

Private: “Only your city is shown. Your postal code stays private.” Finding: “Finding 20121…”. Found, on Join: “Milan, Lombardy — pinned at city level. 13° and foggy right now.” Found, on Profile & Settings: “Toronto, Canada. Your pin moves here when you save.”

Not found names the postal code, the country and the form that country’s postal codes take, with an example: “We couldn’t find “2012” in Italy. Italian postal codes have five digits, like 20121.” On Profile & Settings it adds “Your pin stays in Milan.” When the lookup itself fails, it is never the postal code that is blamed: Profile & Settings shows an alert that says the postal code could not be checked, and Join switches the postal code off and asks for the city instead: “Postal code lookup is down right now, so pick your city instead. Your pin goes to its centre.”
